Пояснения:

- **Перенос текста** — главная причина твоего «двигай экран». Все лейблы должны иметь `TextWrapWord`, а из мобильных панелей убраны элементы с фиксированной шириной. Это займёт у ИИ больше всего времени, но именно это лечит «везде так».
- **Терминал** — делаем честное `user@termai:~$` в истории команд (как в реальном линуксе), а у поля ввода короткий `$`. Плюс вывод на мобильном переводится на `TextGrid` — он не вызывает клавиатуру при тапе, это и фикс проблемы 3 частично.
- **Клавиатура** — если ИИ сделает всё из проблемы 3, а клавиатура всё равно не откроется, это уже баг Fyne на конкретном устройстве — тогда присылай модель телефона/версию Android, будем обходить через явный `Focus()` по тапу через кастомный tap-детектор.
- **Единственное изменение десктопа** — приглашение в истории команд станет `user@termai:~$` вместо `$`.

После выполнения ИИ: `go run .` (проверь десктоп) → commit → push → новый тег `v1.1.3` → новый APK → проверяй на телефоне: теория без горизонтального скролла, промпт в терминале, клавиатура по тапу, плашка ключа при первом запуске.

### Промпт: починить релизную сборку TERMAI на GitHub Actions

Файл: .github/workflows/release.yml. Симптомы: android собирается, linux падал на "wayland-client-core.h: No such file or directory" (и может упасть дальше на xkbcommon), macOS статус неизвестен. Требуется привести все джобы к рабочему виду.

1. Linux: в apt-установку добавить libwayland-dev libxkbcommon-dev (обе обязательны для Fyne 2.8: glfw теперь собирает Wayland-бэкенд). Итог: `sudo apt-get update && sudo apt-get install -y libgl1-mesa-dev xorg-dev gcc libwayland-dev libxkbcommon-dev`
2. Все джобы: go-version: "stable" (не "1.23" — go.mod проекта может требовать новее). Для android-джобы после setup-go добавить: `echo "$HOME/go/bin" >> $GITHUB_PATH` (иначе fyne-cross не найдётся).
3. Windows: джоба с msys2 + mingw-w64-x86_64-gcc (gcc обязателен для cgo Fyne). Если уже так — не трогать.
4. macOS: две сборки в одной джобе: arm64 и amd64 (GOARCH), без xcode-настроек — Fyne/macOS собирается нативно через osximage, дополнительное не нужно.
5. release-джоба: needs: [linux, windows, macos, android], download-artifact с merge-multiple: true, файлы прикладываются через softprops/action-gh-release.

### 10.2. Python — честные плюсы и минусы

Python может дать тебе **UI-десктоп** (PySide6/Tkinter) и даже **Android** (Kivy/BeeWare), но не тот же самый код. Перенос — это переписывание всего с нуля.

**Плюсы Python:**
- Писать быстрее, кода меньше; возможно, тебе он более знаком.
- Аудио/ML-экосистема богаче: whisper-сценарий в Python был бы проще.
- Прототипы и эксперименты — быстрее.

**Минусы — и вот тут всё решается:**

1. **APK.** Ключевое. Kivy на Android: APK весит 60–90 МБ, собирается через Buildozer — больнее, чем fyne-cross, и капризнее. BeeWare — молод и шаток. Fyne-путь, который уже пройден, объективно зрелее. И это переписывание UI дважды: десктоп + мобильный.
2. **Производительность UI.** TERMAI постоянно перерисовывает терминал, списки, RichText. PySide6 справится, Tkinter начнёт тормозить на длинном выводе. Fyne-версия это делает без вопросов.
3. **Один бинарник.** Go = один файл, скачал и запустил. Python = PyInstaller-сборка 80–150 МБ с антивирусными срабатываниями, либо «установи Python, потом pip install».
4. **Потеря готового.** Сейчас есть: рабочий мультикурсовой движок, 5 ролей ИИ, проверка по истории, экзамены, закладки, достижения, хоткеи, fast-path, порт на Android, CI на 4 платформы. Python-перенос = недели чистого переписывания, чтобы получить то же самое с новыми багами.
5. **Pure-Go SQLite** — под Android уже работает без CGO-танцев.

**Вердикт:** для TERMAI как продукта — **оставаться на Go**. Python оправдан, если бы: проект начинался с нуля, цель была только десктоп, ты пишешь на Python сильно свободнее и планируешь сам поддерживать код. Ни одно из этих условий не выполняется.

Когда Python реально стоит рассмотреть: если появятся фичи тяжёлого ML (локальный STT/TTS потоком, офлайн-LLM) — их делают Python-сервисом **рядом**, а не переписыванием UI. Гибрид: TERMAI на Go + опциональный локальный хелпер на Python.
